# 2026-10-30 验证：DSH 0.2.1-rc.5（dsh-web-search-pro 0.2.3）

结论：npm 已发布的 `dsh-web-search-pro@0.2.3` 在新宿主 `@deepseek-ai/dsh@0.2.1-rc.5` 上干净安装、加载、`web_index` / `web_call` 可用、设置卡片渲染与保存都正常。**插件源码与 peer 范围零改动**（`>=0.2.0-rc.2 <0.2.1-0 || >=0.2.1-rc.2 <0.2.2-0` 本来就覆盖 rc.5）。只把 rc.5 加进 `test:peers` 的受支持基线和文档里的“实测”列表。

执行者是开发者侧代理，不是独立验证者。只写亲眼看到的结果。截图、日志、脚本在仓库外的 `research/experiments/dsh-rc5-2026-10-30/`（`wsp-*.png`、`logs/`、`scripts/`）。

## 被测对象与环境

- 宿主：`npm i --prefix <scratchpad> @deepseek-ai/dsh@0.2.1-rc.5 --registry https://registry.npmjs.org`（dist-tag `next`），顶层 `@deepseek-ai/cordis` 4.0.5、`@deepseek-ai/schemastery` 3.18.5，与 rc.4 的依赖版本相同。npm 在安装宿主时给出一条 `install-scripts` 提示（`node-pty`、`koffi` 等 5 个包的安装脚本没有被允许运行）；下面的检查没有用到这些脚本，宿主的 headless / web 都照常启动。
- 源码对照：`git diff dsh-v0.2.1-rc.4 dsh-v0.2.1-rc.5` 只改了 `packages/client/ui-chat` 的推理块（reasoning）渲染、`cordis-client-runner` 的 slot 目录和 `client-ui-cot-translation`，以及各包 `package.json` 的版本号（没有依赖变化）。本插件用到的接口（设置 `mutate`、RPC、凭据、`tools/pre-execute`、`ui-primitives`、`plugins.bundle.config` 槽位）不在其中。
- 插件：npm 上已发布的 `@anweat/dsh-browser@0.2.2` 与 `dsh-web-search-pro@0.2.3`，像新用户一样装，不用本地 tgz。
- 隔离：每项检查用全新的 `DSH_HOME`（scratchpad 下），没有读写 `~/.dsh`，没有占用 19387（Web 用 3399），没有碰桌面端，没有读凭据文件，没有填 API Key（首次打开的“开始使用”对话框用 Escape 关掉），没有跑模型会话、登录类命令和 opencli 站点命令。`npm_config_registry=https://registry.npmjs.org`。

## 1. 干净安装（npm 发布版）

`dsh plugin --profile <p> add @anweat/dsh-browser@0.2.2 dsh-web-search-pro@0.2.3`，web 与 headless 两个 profile，全新 `DSH_HOME`。

| 嵌套 pnpm | web | headless | 警告 / 错误 |
|---|---|---|---|
| 11.7.0（PATH 垫片） | 退出码 0 | 退出码 0 | 无 |
| 12.4.2（这台机器的默认 pnpm） | 退出码 0 | 退出码 0 | 无（只有 pnpm 的“Update available”提示） |

两种 pnpm 下 `Packages: +25`，`dsh.profile.bundles` 里都有两个插件；`--dump-config`（headless）含两个插件的层。日志：`logs/install-npm-pnpm11.7.0-*.log`、`logs/install-npm-pnpm12.4.2-*.log`、`logs/dump-config-headless.txt`。

## 2. headless（无模型）

方法同 2026-10-28 的记录：一次性探针插件（scratchpad，不在仓库里）在启动后用宿主自己的 `ctx.tools.execute` 调工具。为了不走模型，探针 profile 里关掉了 `llm-deepseek` 和 `headless-runner` 两行（否则宿主在没有 API Key 时 `MISSING_CREDENTIAL` 退出）。两个插件都加载，启动日志为空（没有 `incompatible`、没有错误）。

- 工具列表含 `web_index`、`web_call`、`browser_index`、`browser_call`（外加宿主自带的 `web_search`、`web_fetch`）。
- `web_index({})`：1818 字符，列出 search / read / history / sources / rules / cache / config 七个分组。`web_index({group:'config'})` 列出动作。
- `web_call sources.status`：15 515 字符，列出全部来源（`ddg`、`bing`、`exa`、`seam` 等 `ready`；`jina` 无 Key 时 `unavailable`；`github-code` 等需要登录的显示 `login unverified`）。
- `web_call config.inspect`：覆盖层 revision 0，`engines [configuration]: ddg > bing > exa > seam > jina`，没有自定义 CLI。

日志：`logs/probe-headless-indexes.json`、`logs/probe-headless-groups-status.json`。

## 4. 本仓库测试

`pnpm run verify`（pnpm 11.7.0，`DSH_HOME` 隔离）通过：typecheck、`test:peers`（受支持基线 0.2.0-rc.2、0.2.1-rc.2 ~ rc.5，拒绝 0.1.7-rc.2、0.2.0-rc.1、0.2.1-alpha.5、0.2.1-rc.1、0.2.2-alpha.1）、build、1002 项测试（994 通过、0 失败、8 跳过，跳过的是需要真实 CLI / 登录的 live 测试，数字与 0.2.3 发布时相同）、client bundle 检查、docs 链接检查。日志：`logs/verify-wsp.log`。

用宿主自带的 semver 7.8.5 复核：`0.2.1-rc.5` 在 runtime（`includePrerelease`）与 install（默认）两种解析下都满足 peer 范围；`0.2.2-rc.1` 两种都拒绝。
